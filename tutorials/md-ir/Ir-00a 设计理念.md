Weave Incremental Reading 把「以后再看」变成可排期、可续读的阅读队列。本章说明为什么这样设计，以及它不是什么。

## 收藏不等于读过
稍后读、书签、剪藏文件夹解决的是「先存下来」。它们通常不回答：今天该读哪几条、逾期怎么办、同一本书拆成多段后怎样顺着读、打开时能否回到当初的位置。

本插件把材料收成**阅读点**，用**日历**做每日节奏，用**溯源链接**保证续读——目标是让队列真正动起来。

## 三个设计原则
1. **决策在日历，内容在原文**：日历负责选日、负载、优先级、进度与改期；打开阅读点即回跳 Markdown / PDF++ / Canvas / 网页 / EPUB。主路径是队列 + 回跳，而不是再嵌一套日常「第二阅读器」。
2. **一条主路径，多种入口**：日常新增走日历顶部的**添加链接**（命令侧常写作「添加阅读目标」）。导入留给整份文档 / 整书目录；订阅文件夹留给剪藏收件箱持续补齐（高级功能）。
3. **增量阅读 ≠ 间隔复习（FSRS）**：本插件管读什么、何时再出现、如何续读；Weave Deck 管记住什么、间隔多久复习。教程与设置里的调度，指的都是阅读点日程，不是 FSRS。

## 为什么用专题（.irdeck）
专题把阅读点按主题或计划分组，并以库内 `.irdeck` 文件保存：可备份、可同步；打开后可在专题视图与日历之间切换；月历标题旁的专题 chip 可过滤「全部」或某一专题。命名请保持稳定，避免同一计划碎成多个拼写不同的专题。

## 免费基线与高级扩展
默认保证：**日历 + Markdown 阅读点 + 添加链接 + 基础调度 + 连续阅读** 即可完成闭环。PDF/EPUB 批量章节、订阅文件夹、深度调度策略、计时器、统计、关联笔记等属于高级扩展——需要时再激活，不挡主流程。

## 不要当作日常方案
1. 旧增量阅读主阅读界面：已移除，旧入口会转到日历。
2. 段落阅读工作台：实验设计，未就绪；请用日历侧栏。
3. 依赖标签组做主流程：仍在完善中；请先用专题、优先级与基础调度。
4. 用 FSRS「代替」本插件调度：职责属于 Weave Deck。
