### 为何需要手动把书加入书架，而不采用自动扫描库中书籍全部自动添加到书架中

书架中的书籍为你需要阅读、深度阅读的书籍，需要你做出选择。加入方式可以是：扫描 Vault 勾选、从仓库外直接导入文件，或在文件浏览器中打开支持格式后再用阅读器打开。若你需要藏书馆式的「全库书目」，推荐使用官方的 Bases 数据库或其它插件的数据库功能：在库中添加附件地址或书籍链接，点击后默认以本阅读器插件打开即可。

### 为何不以自动记录阅读位置作为默认设计？

该阅读器插件不同于其它独立阅读器插件，很多设计在 Obsidian 环境下有着不同的考虑。在 Obsidian 使用本阅读器插件更倾向于输出内容，可配合 Markdown、Canvas、Excalidraw、Weave Review，还有其它插件使用。用户会频繁通过摘录笔记中的溯源链接跳转书籍的不同位置查阅翻看原文内容，自动把每一次跳转都写成「最后阅读位置」容易错误更新续读点。阅读进度位置与最后查看位置不应该被混淆。

更贴合实体书体验的做法，是主动「钉」一处接着读位置：可选中段落钉住精确锚点，再次打开时定位并短暂高亮；当前页书签则适合一章里多处标记。线性连读时，也可在设置中开启「连续阅读达到设定页数后自动保存」——它服务的是稳定向前读，而不是把溯源翻看当成续读。

### 高亮时的摘录笔记：为何默认按书建一份 md，同时又保留完全自由的落点？

常规阅读器往往只有「内置高亮库」一条路。Obsidian 里更常见的需求是两头都要：既要划一下就能留下可回链的笔记，又要能把摘录写进任意文章、Canvas 或牌组。

因此阅读器把路径拆开：

1. **高亮自动写入书籍摘录笔记**（设置项，默认开启）：未开顶部「自动化」时，对正文高亮会按书名在 Obsidian 新笔记默认文件夹创建（或追加到已有）一份摘录 Markdown，带书籍溯源，正文可回显。适合「先划再说、稍后再整理」。
2. **顶部「自动化」**：开启后，高亮优先插入**当前**打开的 Markdown 光标处，或已绑定的 Canvas，形成你指定工作流里的摘录。适合边读边写进某一篇笔记。
3. 你仍可自建任意 md、多文件读书笔记、脑图 Canvas；阅读器会汇总散落各处的摘录并在原文回显。不需要自动建笔记时，可在设置中关闭「高亮自动写入书籍摘录笔记」。

自由落点没有消失；默认按书建笔记，只是把「第一次划线就能留下来」补上了。

### 是否集成 AI？

现阶段，并不考虑在阅读器插件中集成 AI 能力。愿景是在 Obsidian 中为你提供干净、沉浸式的阅读环境，流畅自然的功能交互设计，以及舒适的文本编辑体验。无意于通过 AI 满足自动解析、总结或对话式辅读等功能需求。多数情况下该实现可能打乱你的阅读节奏，分散阅读专注，中断阅读过程中的深度思考。

如有相关需要，可复制内容、或导出当前章节为 MD 文件，或通过插件提供的 API 功能获取章节内容、摘录笔记等，协同其它具有 AI 能力的插件使用，实现各种自动自定义的内容。阅读器的 API 功能正是为此而设计的。

### 为何不把「阅读时长仪表盘」当成核心？

如前所说，处于 Obsidian 的笔记环境中，有些常规阅读器的考虑并不适用。常规阅读器往往假设一段平缓、连续的阅读任务，把墙上时钟式的累计时长当成主指标。但在 Obsidian 中，停顿一页正文去写一段笔记并不少见；从 md 里的溯源链接跳回书中核对一句，然后又跳走，也是常有。把每一次停留都算进「读了多久」，很容易把查阅、写笔记与真正的专注阅读混在一起。

因此阅读器不追求堆砌更重的时长仪表盘。若需要专注节奏，可用阅读器内的番茄专注计时（按真实阅读时长累计）；若要感知本章 / 全书还要多久，可用剩余阅读时间贴纸；若要回顾足迹，内容区书架主页的「统计」与活动热力已覆盖常用回顾。更复杂的指标，仍可用 Dataview 或官方 Bases 等自行搭建。

### 为何不内置听书 / 朗读？

听书、全文朗读与本插件「阅读—摘录—笔记」的主路径并不一致：边听边划、边听边写想法，节奏与选区、溯源回链很难自然咬合。内置一套 TTS / 听书栈，也会把阅读器拖向多媒体播放器，偏离专注正文与输出。

如有需要，可用系统选区朗读、导出当前章节为 Markdown，或经公开 API 把章节正文交给其它 TTS / 听书插件处理。

### 为何不内置 RSS 订阅？

RSS 属于信息流入与订阅管理，和「打开一本书、沉浸阅读、落笔摘录」是另一条产品线。把订阅源、未读队列、推送刷新塞进阅读器，会稀释书架与正文体验，也很难做得比成熟的 RSS 工具更专业。

若你需要在 Obsidian 里读订阅内容，推荐使用 [qiaomu AI RSS](https://github.com/joeseesun/qiaomu-ai-rss) 等专门插件；需要精读的材料，再自行导入或衔接本阅读器与增量阅读工作流即可。

### 还有哪些能力刻意不内置？

边界留在专注阅读与摘录，延伸交给更合适的工具。例如：内置词典交给 Finger 等划词插件；PDF 深度批注交给 Obsidian 自带查看器或 PDF++（书架仍可收录 PDF）；独立换肤与背景色选项跟随 Obsidian 主题与 CSS 片段。公开 API、导出 Markdown、与 Canvas / Excalidraw / Weave Review / 增量阅读协同，是扩展面；把生态里已有且往往更专业的能力再内置一遍，则不是方向。
